### Image hardening and supply chain

The controller and executor images are built from a minimal `ubuntu:noble` base with a headless JRE. The build installs only the required packages, removes documentation, locale data and setuid binaries, and uses `COPY` instead of `ADD` for image contents.

Every release image pushed to the registry ships with two attestations, generated by the release workflow:

- **SBOM** - the complete list of packages inside the image.
- **Provenance** - a SLSA attestation that records how the image was built, from which source revision, and by which workflow.

You can inspect the attestations for a released image with `docker buildx`:

```shell
docker buildx imagetools inspect ghcr.io/phonepe/drove-controller:latest
```

The output shows the image manifest along with the `sbom` and `provos` attestation manifests.

If you use a tool like `cosign`, you can verify the attestations against the image digest:

```shell
cosign verify-attestation \
    --type slsaprovenance \
    ghcr.io/phonepe/drove-controller@<digest>
```

!!!note
    Attestations are attached to images pushed by the release workflow. Images you build locally do not carry them.

!!!tip
    If your organization pins images by digest, record the digest at deploy time. The attestation is bound to the digest, so the digest is all you need to audit what runs in your cluster.
